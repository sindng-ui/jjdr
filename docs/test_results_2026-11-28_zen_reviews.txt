## Pre-Release Resource / CPU / Traffic Audit (v0.5.4)
1. **React Render Isolation (`ZenReviewsView`, `ZenIncomingReviewsColumn`, `ZenOutgoingReviewsColumn`, `ZenModeView`)**:
   - Removed `allSessions` subscription from `ZenReviewsView`; `ZenIncomingReviewsColumn` now subscribes only to a primitive key of live matching review terminal addresses -> **0 re-renders** during normal terminal streaming.
   - Memoized `peerStatusByHandle` (`Map`) in `ZenOutgoingReviewsColumn`, memoized callbacks in `ZenModeView` / `ZenReviewsView`, and short-circuited Reviews auto-return with primitive `actionableKeysSig`.
2. **Relay & GitHub Traffic Protection (`ZenReviewsView`, `commands/team.rs`)**:
   - Added 5-second auto-refresh cooldown on `ZenReviewsView` mount (manual `Refresh` button remains immediate).
   - Added per-project async lock (`open_pr_project_lock`) in `list_my_open_prs` to coalesce concurrent requests onto the 20s cache, plus 60s stale entry pruning.
3. **Track B CPU Optimization (`useTrackBPrDetector.ts`)**:
   - Added per-session cheap signature cache (`lastCheckedSigRef`) so regex scanning only runs when a session's turn/status/tail line actually changes; prunes closed sessions.
4. **Connection Pooling (`src-tauri/src/team/http.rs`)**:
   - Cached static `OnceLock<reqwest::Client>` pools (`no_proxy` and default) instead of rebuilding HTTP clients per REST call.
5. **Windows Child Process Leak Prevention (`author.rs`, `identity.rs`, `reject.rs`)**:
   - Added `cmd.kill_on_drop(true)` to all 5 `tokio::process::Command::new("gh")` invocations so timed-out `gh` processes terminate immediately.
6. **Relay Startup Wakeup Fix (`commands/system.rs`, `SettingsModal.tsx`, `TeamOrchestrationSettingsTab.tsx`)**:
   - `load_persisted_bundle` now calls `state.team_relay.notify_config_changed()` so Relay wakes automatically when settings hydrate from `herdr`.
   - `SettingsModal` surfaces real `saveSettings` errors instead of swallowing them; added `Reconnect` button & unsaved-draft notice in `TeamOrchestrationSettingsTab`.
